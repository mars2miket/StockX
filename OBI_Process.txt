Product Requirements Document (PRD) & Engineering Prompt
Project Overview
Objective: Build an institutional-grade Order Book Imbalance (OBI) algorithmic signal generator.
Core Philosophy: Traditional OBI models based on raw, aggregated Level 2 data are easily gamed by spoofing and phantom liquidity. This architecture fixes those vulnerabilities by combining Level 3 (Market-by-Order) granularity with institutional tape-reading frameworks (tracking real aggression vs. passive intent).
Target Environment: Python / C++ streaming architecture utilizing Databento's raw proprietary exchange feeds (e.g., Cboe EDGX, MEMX).

Technical Specifications & Mathematical Logic

1. ECN-Isolated, Depth-Weighted OBI
Instead of a generic, aggregated broker feed, input data must be sourced strictly from direct venue feeds via Databento (e.g., EDGX.PITCH, MEMX.MEMOIR).
The model must calculate a depth-weighted OBI across 10 levels, applying an exponential decay weight 

(\(w_{i}\)) to favor liquidity closest to the National Best Bid and Offer (NBBO).
\(\text{OBI}_{t}=\frac{\sum _{i=1}^{10}w_{i}\cdot \text{Bid}_{i,t}-\sum _{i=1}^{10}w_{i}\cdot \text{Ask}_{i,t}}{\sum _{i=1}^{10}w_{i}\cdot (\text{Bid}_{i,t}+\text{Ask}_{i,t})}\)
Where: \(w_i = e^{-\lambda (i-1)}\) and λ is a tuning parameter (default = 0.35).

Output Range: -1.0 (pure sell-side depth) to +1.0 (pure buy-side depth).

2. Level 3 Hidden Liquidity & Queue Tracker (Anti-Spoofing)
To neutralize phantom walls and spoofing, the AI must leverage Databento's Market-by-Order (MBO) schema to track individual order IDs, cancellations, and queue updates.
The Logic: Do not rely on basic time-duration persistence filters. Instead, evaluate the Realized Execution Ratio (RER) of large resting blocks.
The Rule: If a massive resting size is detected, track its Order ID. If price approaches that level and the order is canceled without absorbing volume, flag it as Spoofing and discard it from the OBI calculation. If the order stays in place and actively absorbs volume, classify it as a True Price Wall.
Iceberg Detection: Monitor the Best Bid/Offer for Refreshing Orders. If the visible size is small (e.g., 100 shares) but Time & Sales continuously executes large volume against it without the price moving, calculate the hidden volume size and add it dynamically to the OBI calculation.

3. Order Flow Aggression Ratio (Intent vs. Action)
The order book represents passive intent. The system must cross-reference this intent against action from Time & Sales (executed trades) to calculate the Aggression Ratio (AR) over a rolling window (e.g., 500ms to 1s).
\(\text{AR}=\frac{\text{Aggressive\ Buy\ Volume\ (Market\ Orders\ hitting\ Ask)}}{\text{Aggressive\ Sell\ Volume\ (Market\ Orders\ hitting\ Bid)}}\)

4. Dynamic Per-Symbol Baselines
The system must reject hard-coded volume thresholds. It must maintain a rolling 20-day historical baseline of average book depth and trade velocity per individual ticker.
A 10,000-share wall on a low-float momentum ticker should trigger maximum weighting, whereas the same size on a mega-cap asset should be treated as minor noise.

Output Engine: Composite Confidence Score
The system must output a unified, dynamic Confidence Score (0–100) instead of a binary buy/sell metric.

Signal Logic Matrix
🟢 System Status: [BUY/LONG] Triggered when the Depth-Weighted OBI is positive, the MBO Queue confirms a verified institutional buy wall (or iceberg buyer) holding the floor, and the Aggression Ratio confirms market orders are rapidly chewing through resting sell offers.
🔴 System Status: [SELL/EXIT] Triggered when the Depth-Weighted OBI is deeply negative, a persistent institutional sell wall is confirmed via MBO order tracking, and aggressive market sell orders are dominating Time & Sales.
⚪ System Status: --- (Neutral) Triggered when OBI is high but unconfirmed by trade flow volume, or if order logs show high cancellation rates (spoofing).
